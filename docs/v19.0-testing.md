# Simple Machines v19 acceptance

The v19 migration targets Debian 13 (Trixie) and Simple Machines Forum 2.1.7.
The build downloads the official `v2.1.7` tag archive from the Simple Machines
GitHub repository and verifies SHA-256 digest
`2c9c0ea7df803ee03ff7755ea3651c680952e264b7c572439902bb18245c06a3`.
The tag resolves to upstream object
`d49255b955cbeeb3a702d77009c85aae517ed1e4`.

SMF 2.1.7 can lose the newly created session on a user's first visit, causing
the rendered login form to fail token validation. The build also applies the
official upstream correction merged as commit `375bcd1` for SMF 2.1.8. Its
patch digest is
`2641f0fce520d4c2360e40a43498ffa4ce36dceb8fb890503c6073b854b4daec`.

## Acceptance crosswalk

| Contract | Evidence in `tests/v19.sh` |
| --- | --- |
| First boot and services | Apache and MariaDB must be active after first-boot configuration. |
| HTTPS | The forum front page must load over HTTPS. |
| Administrator login | The rendered login form supplies its session and login tokens; the configured `admin` account must reach authenticated administration links. |
| Board and topic workflow | The Simple Machines board and post APIs create a board and topic, and both must be readable through public HTTPS pages. |
| Database persistence | MariaDB must contain the exact board name, topic subject, and message body created through the application APIs. |
| Update discovery | `simplemachines-update --check` must report installed and latest stable 2.1 versions from the official GitHub release channel without changing the installation. |
| Cleanup | The created topic and board are removed through Simple Machines APIs, then database absence is verified. |

Run the appliance acceptance through the v19 harness. The harness supplies the
application password in `TKL_TEST_APP_PASS` and the retained result path in
`TKL_TEST_RESULT`. The script executes inside the appliance and resolves the
configured application domain to the local HTTPS service.

## Deferred items

Automatic application upgrades remain intentionally out of scope because SMF
upgrades can require database migrations and operator review. The appliance
provides stable-release discovery, while the existing documented supervised
upgrade boundary remains unchanged.
